# لُقطة — تطبيق أندرويد

تطبيق تنزيل فيديو وصوت وصور، بواجهة لُقطة العربية ومحرك yt-dlp وFFmpeg وQuickJS مدمج. لا يحتاج Termux أو خادمًا خارجيًا.

## التثبيت على جوالك

1. نزّل `Luqta-Android.apk` وافتحه.
2. إذا طلب أندرويد السماح بالتثبيت من هذا المصدر، فعّل الإذن لتطبيق التنزيل الذي تستخدمه ثم أكمل التثبيت.
3. افتح «لُقطة» وانتظر تجهيز المحرك عند أول تشغيل. قد يستغرق هذا بضع ثوانٍ ويستهلك مساحة إضافية لفك ملفات التشغيل.
4. السماح بالإشعارات اختياري، ويتيح رؤية تقدم التحميل خارج التطبيق.

هذه النسخة لأجهزة ARM64 بنظام أندرويد 10 أو أحدث، ومنها Samsung Galaxy A54. التطبيق موقّع بمفتاح تطوير خاص بهذا المشروع للتثبيت المباشر؛ لم يُنشر على Google Play.

## تحديث 1.6.1 — متابعة تحويل تيك توك وإكمال التوافق

رقم الإصدار 9، بنفس الحزمة والتوقيع. أصبح تحويل تيك توك يعالج المقاسات الفردية ويحد الضلع القصير عند 1080 والطويل عند 1920، دون قص أو تكبير. تُعرض نسبة التقدم في السجل والإشعار، وتعمل خدمة الخلفية أثناء التحويل. يمكن إلغاء التحويل، ويُمنع تكراره أو حذف ملفه أثناء تجهيزه. بعد النجاح يُشارك الملف المحفوظ من زر «مشاركة نسخة تيك توك» دون إعادة التحويل؛ يبقى الأصل متاحًا. إذا توقف التطبيق أثناء التحويل تظهر حالة تسمح بإعادة المحاولة عند فتحه، وإذا اكتمل أثناء غياب الواجهة تبقى النسخة جاهزة للمشاركة لاحقًا.

## تحديث 1.6.0 — نسخة متوافقة مع تيك توك

رقم الإصدار 8، بنفس الحزمة والتوقيع لتثبيته فوق النسخة السابقة. يظهر زر «نسخة تيك توك» للفيديو المكتمل في سجل التنزيلات. ينشئ ملف MP4 منفصلًا بترميز H.264 وصوت AAC وعمق ألوان 8-bit yuv420p، ويحد معدل الإطارات عند 60 FPS والدقة عند 1080×1920 أو 1920×1080 مع حفظ نسبة الأبعاد كاملة دون قص. يبقى الفيديو الأصلي كما هو، وبعد اكتمال التحويل تُفتح خيارات المشاركة في أندرويد.

## تحديث 1.5.1 — أيقونات المنصات

رقم الإصدار 7، بنفس الحزمة والتوقيع لتثبيته فوق النسخة السابقة. تظهر أيقونات تيك توك ويوتيوب وإنستقرام الملونة في الصفحة الرئيسية، ومع اسم المصدر في معاينة الرابط وسجل التحميل، وعلى أزرار ربط إنستقرام وتيك توك. الأيقونات SVG مضمّنة في الواجهة المحلية، وتستخدم تعريفًا واحدًا لكل شعار دون تحميل خطوط أو صور خارجية. أسماء المصادر والعناوين تستمر بالنص الآمن، وتبقى أسماء المنصات ظاهرة بجوار الأيقونات لتوضيح معناها.

## تحديث 1.5.0 — حماية الاتصالات وفصل التوقيع

ثبّت APK 1.5.0 فوق النسخة السابقة. رقم الإصدار 6، بنفس شهادة التوقيع للحفاظ على السجل والإعدادات.

- يُقبل HTTPS فقط على المنفذ 443 في الواجهة وأندرويد ومحرك Python. حُظر HTTP في إعداد التطبيق. قد تتوقف الروابط القديمة التي توفر HTTP فقط؛ استخدم رابط HTTPS يقدمه المصدر.
- تُفحص طلبات صفحة المصدر والوسائط والصور وبيانات HLS/DASH وأجزائها وتحويلاتها. يستخدم yt-dlp ناقل urllib واحدًا بفحص الشهادة واسم الموقع وTLS 1.2 أو أحدث؛ تُمنع ناقلات البروكسي وcurl والاتصال بالعناوين الخاصة. يُفحص العنوان الرقمي الفعلي عند socket.connect لمنع تبديل DNS من عنوان عام إلى عنوان محلي.
- تنزيل HLS/DASH يتم داخل ناقل Python الخاضع للفحص. تُرفض مسارات النقل الخارجية أو حالات HLS التي تحتاج تفويض FFmpeg. FFmpeg وFFprobe يعالجان ملفات محلية فقط، ببروتوكولات file/pipe وقائمة صيغ تستبعد قوائم التشغيل ذات مراجع الملفات أو الشبكة؛ حماية منفصلة لكل مدخل عند دمج الصوت والفيديو. تُستخدم EJS المدمجة بدل تحميل كود JavaScript إضافي تلقائيًا.
- جسر الواجهة يُستخدم من index.html المحلي فقط. تُحظر المستندات الخارجية والإطارات والنماذج، ويُزال الجسر إذا بدأ تحميل صفحة غير موثوقة. نافذة دخول المصدر منفصلة دون جسر التطبيق.
- مفتاح التوقيع وكلمات مروره خارج المشروع وحزمة الكود. سكربت البناء يتطلب مفتاحًا خارجيًا وملف كلمة مرور بصلاحيات خاصة، ولا يولّد مفتاحًا افتراضيًا أو يضع كلمة المرور في وسيطات الأمر. سكربت تجميع المصدر يرفض ملفات المفاتيح والأسرار.

**حد التوقيع:** الحزم المصدرية القديمة كانت تحتوي مفتاح التطوير. حذف المفتاح من الحزمة الجديدة وتغيير كلمة مرور نسخته الحالية لا يلغيان نسخ المفتاح القديمة التي سبق مشاركتها. استمر استخدام الشهادة نفسها لأن تغييرها يكسر التحديث المباشر المعتاد؛ النشر العام يحتاج خطة توقيع منفصلة وحماية المفتاح القديم أو استبداله بمسار انتقال مدروس.

فحوص الحماية تشمل اتصال TLS فعليًا بشهادة اختبار، رفض الشهادة غير الموثوقة واختلاف اسم الموقع، منع التحويل إلى HTTP أو عنوان خاص، منع URL مستخرج أو جزء HLS غير آمن وتحويلاته، تبديل DNS عند الاتصال، ملفات قوائم تشغيل مزيفة، حماية مدخلي الدمج، حصر file:// في المقطع المدمج، ورفض تضمين المفاتيح في المصدر. خادم TLS محلي متحكم فيه؛ استُبدلت نتيجة DNS وتصنيف عنوان الخادم فقط أثناء فحوص النقل، وفُحص منع العناوين الفعلية في عامل مستقل دون هذا الاستبدال. هذه فحوص حماية محددة في بيئة Linux، وليست اختبار اختراق شاملًا أو ضمانًا لأمان كل الاعتماديات. يلزم تجربة APK على هاتف فعلي.

المراجع: [توقيع التطبيقات](https://developer.android.com/studio/publish/app-signing)، [جسور WebView](https://developer.android.com/privacy-and-security/risks/insecure-webview-native-bridges)، [سياسة الشبكة](https://developer.android.com/privacy-and-security/security-config)، [بروتوكولات FFmpeg](https://ffmpeg.org/ffmpeg-protocols.html#Protocol-Options).

## تحديث 1.4.0 — صور المنشور الكاملة والألبومات والحذف

ثبّت APK 1.4.0 فوق النسخة السابقة. رقم الإصدار 5، بنفس الحزمة والتوقيع للحفاظ على السجل والإعدادات.

- **صور كاملة:** إنستقرام وتيك توك يستخدمان بيانات صور المنشور بدل صورة `og:image` والمعاينات والأغلفة. يستخرج إنستقرام عناصر `carousel_media` أو `edge_sidecar_to_children` ونسخ الصور، ويستخرج تيك توك `imagePost.images` أو `image_post_info.images`. تُستبعد النسخ التي تختلف نسبة أبعادها عن الصورة الكاملة، وتُفحص الأبعاد من البايتات قبل التنزيل. إذا منع المصدر جلب البيانات الكاملة، تظهر رسالة واضحة ويُرفض تنزيل صورة المعاينة بدلاً منها. لا يمكن استعادة الجزء المفقود من ملف مقصوص سابقًا؛ يلزم تنزيله مجددًا من رابط المنشور.
- **اختيار الجودة:** درجات 240، 360، 480، 720، 1080، 1440، 2160 و3840 بكسل عندما لا تتجاوز حجم المصدر، ثم «أعلى جودة أصلية». هذه حدود للضلع الطويل للصور، وتختلف عن 2160p للفيديو. الدقة الأقل تُصغّر الصورة كاملة باستخدام FFmpeg مع حفظ نسبة أبعادها دون قص؛ الأصلية تبقي البايتات كما قدمها المصدر. لا يُرفع حجم صورة صغيرة اصطناعيًا. خيارات الصورة الواحدة تعتمد على دقتها، وخيارات الألبوم تعتمد على أصغر حد متاح في الصور المختارة لتجنب طلب جودة أعلى من المصدر.
- **الألبومات:** اختيار «كل صور المنشور» هو الافتراضي للألبوم؛ يمكن اختيار صورة منفردة أيضًا. حتى 50 صورة من رابط واحد، بترتيب المنشور وأسماء تبدأ برقم الصورة، وتقدم وحفظ لكل صورة في السجل. فحص الألبوم محفوظ مؤقتًا في المحرك لمدة 15 دقيقة، ثم تُضاف مهامه دفعة واحدة إلى سجل ذري. الطابور يتسع إلى 100 مهمة، والتنزيل يبقى متتابعًا. تُتجاوز الفيديوهات في الألبوم المختلط وتبقى أرقام مواقع الصور الأصلية.
- **الحذف:** زر «حذف من السجل» لكل عنصر، بما فيه المكتمل غير المحفوظ. تأكيد الحذف يوضح أن نسخة التطبيق والأجزاء تُحذف وأن ملفات المعرض تبقى. حذف مهمة جارية يوقف عاملها، ثم ينظف ملفاتها بعد توقفه؛ أحداث العامل المتأخرة لا تُعيد العنصر. تُسجل حالة الحذف حتى لا تستعيد آلية الملفات القديمة عنصرًا حذفته. مسح السجل المنتهي يشمل الملفات المكتملة بعد التأكيد؛ المهام الجارية والموقوفة تبقى، ويمكن حذفها منفردة.
- **ربط المصدر عند الحاجة:** زر ربط إنستقرام أو تيك توك في الإعدادات يفتح صفحة الموقع الرسمية في نافذة WebView منفصلة، بلا جسر JavaScript الخاص بلُقطة. تُستخدم جلسة المصدر لقراءة المنشور؛ كلمة المرور لا يقرأها كود التطبيق. لا تُضمّن جلسة المصدر في السجل، ولا تُرسل كوكيز الحساب إلى روابط صور CDN. زر «فصل الحساب» يحذف جلسة الموقع المحفوظة محليًا. قد ترفض المنصة بعض طرق تسجيل الدخول داخل WebView؛ خصوصًا تسجيل الدخول عبر مزود خارجي. الربط والدخول والحفظ عبر MediaStore تحتاج تجربة على هاتف فعلي.

للاستخدام: اختر «صور»، الصق رابط منشور واحد، ثم افحصه. اختر «كل صور المنشور» أو الصورة المطلوبة والجودة، ثم حمّل. للحالة التي أبلغ عنها المستخدم لم يصل رابط المنشور نفسه؛ لذلك لم يُختبر نفس المنشور على المنصة، ولم يتوفر هاتف فعلي. اختبارات المصادر تعتمد بيانات منشورات محكومة، مع تنزيل ملفات صور حقيقية من خادم اختبار؛ لا تعني أن كل رابط حي سيعمل دون قيود المصدر.

## تحديث 1.3.0 — الصور والاستكمال والسرعة

ثبّت APK الجديد فوق النسخة السابقة. رقم الإصدار 4 واسم الإصدار 1.3.0، بنفس اسم الحزمة ومفتاح التوقيع حتى تحتفظ ببيانات التطبيق.

- **الصور الأصلية:** اختر «صور» قبل فحص الرابط. يدعم روابط JPEG وPNG وWebP المباشرة، وصور الصفحات العامة المعلنة في `og:image` و`srcset` ووسوم الصور. يفحص حتى 12 رابط صورة، ويعرض الصور القابلة للقراءة، ويرتبها حسب مساحة البكسل لتختار الصورة المطلوبة. لا ينفذ JavaScript في صفحات المواقع ولا يستورد تسجيل دخول؛ قد تتطلب منشورات بعض المنصات رابط الصورة المباشر.
- **4K للصور:** «الأصلية» يحفظ بايتات المصدر كما هي، بما فيها بيانات الصورة، دون تحويل أو ضغط أو تكبير. «4K فقط» يتطلب ضلعًا طويلًا لا يقل عن 3840 بكسل، بما يشمل الصور العمودية؛ هذا معيار اختيار داخل التطبيق وليس فرض نسبة 16:9. تظهر الأبعاد الفعلية، وتُرفض الصورة الأصغر بدل تصنيع دقة أعلى.
- **إيقاف واستكمال:** أزرار للوقف المؤقت والاستكمال والإلغاء، وزر وقف كل المهام في الإشعار. الوقف يحتفظ بالأجزاء. استكمال الفيديو يستعمل `continuedl` في yt-dlp. استكمال الصور يستعمل Range وIf-Range عند توفر ETag قوي، ويتحقق من Content-Range وETag؛ يبدأ من جديد إذا لم يسمح المصدر باستكمال آمن أو تغير الملف.
- **استرجاع المهام:** الإعداد الافتراضي يعيد المهام التي انقطعت بسبب توقف عملية التطبيق إلى الانتظار ويبدأها عند فتحه. المهام التي أوقفتها يدويًا تبقى موقوفة. عند تعطيل الاسترجاع التلقائي تتحول المهام التي انقطعت إلى موقوفة ويمكن استكمالها يدويًا. السجل يستخدم `AtomicFile` ويُحفظ دوريًا أثناء النقل.
- **تنظيف المساحة:** تُحذف بقايا المهمة بعد الاكتمال مع حماية الملف النهائي غير المحفوظ. بعد نجاح الحفظ العام وتسجيله تُحذف النسخة المحلية المكررة، وتستخدم أزرار الفتح والمشاركة رابط MediaStore الموجود. زر التنظيف يحذف بقايا المهام المنتهية والفاشلة؛ يحمي المهام الجارية والموقوفة والملفات النهائية غير المحفوظة ولا يمس صور وفيديوهات المعرض. الملفات النهائية السابقة التي اختفى سجلها وتوجد منفردة في مجلد المهمة تستعاد إلى السجل. الملفات النهائية القديمة الملتبسة تُترك، وتُحذف البقايا فقط دون تتبع الروابط الرمزية.
- **السرعة:** اختيار 1 أو 2 أو 4 أو 8 أجزاء متزامنة للفيديو المجزأ. الافتراضي 4؛ لا تضمن زيادة العدد زيادة السرعة. الإعداد يطبق عند بدء مهمة أو استكمالها. الصور والفيديو المباشر يستخدمان نقلًا واحدًا. لا يوجد حد مصطنع لسرعة الشبكة.
- **حفظ تلقائي اختياري:** يُفعّل من الإعدادات. الفيديو في `Movies/Luqta`، الصوت في `Music/Luqta`، والصور في `Pictures/Luqta`. عند فشل الحفظ التلقائي يبقى الملف النهائي ويمكن حفظه يدويًا.
- **تنزيل طويل:** أُزيل القطع الثابت بعد 30 دقيقة. يوقف المحرك مهمة لا تعطي أحداثًا لمدة 5 دقائق في مرحلة الشبكة، أو 30 دقيقة في مرحلة تجهيز FFmpeg. قيود خدمات أندرويد تبقى مطبقة، ومع انتهاء مهلة النظام تُوقف المهام مؤقتًا مع الاحتفاظ بالأجزاء.

تحسينات الفيديو السابقة باقية: الدقة هي الضلع الأقصر في الفيديو العمودي أو الأفقي؛ 2160×3840 يُعد 2160p، و1080×1920 يُعد 1080p. أعلى FPS يأتي قبل تفضيل H.264 عند تساوي الدقة. 2160p و120 FPS متاحان فقط عندما يوفرهما المصدر معًا، ولا ينخفض الطلب المحدد تلقائيًا. يتحقق FFprobe من أبعاد الملف النهائي وFPS بعد التنزيل. خيار «الأفضل» و«الأعلى المتاح» يحفظ أعلى المتاح.

المراجع: [خيارات yt-dlp](https://github.com/yt-dlp/yt-dlp#download-options)، [MediaStore](https://developer.android.com/training/data-storage/shared/media)، [Range وIf-Range](https://www.rfc-editor.org/rfc/rfc9110.html#section-14)، [قيود خدمة أندرويد](https://developer.android.com/develop/background-work/services/fgs/timeout).

## إصلاح 403 والتنظيف السابق

- يجلب المحرك رابطًا جديدًا ويعيد المحاولة مرة واحدة عند HTTP 403، ثم يتوقف برسالة واضحة إذا استمر رفض المصدر.
- ليوتيوب فقط، عند فشل التنزيل، يحاول مسار Safari HLS المتاح دون طلب صيغ تتطلب رموز وصول ناقصة. لا يضمن هذا نجاح كل رابط أو توفر كل جودة. WebM يعيد الاستخراج العادي.
- يُحدّث APK المحرك المخزن إذا كان أقدم من المحرك المدمج، ويصلح حزمة نفس الإصدار إذا فقدت أدوات EJS، مع إبقاء نسخة أحدث حدّثها المستخدم.
- تحديث المحرك من الإعدادات يتحقق من وجود yt-dlp وEJS، ويحتفظ بنسخة احتياطية لاستعادتها عند فشل التحديث.
- معالجة بيانات المقطع واختيار الصيغ تتم مرة واحدة لكل محاولة. MP4 يستخدم إعادة تغليف دون إعادة ترميز عند الحاجة؛ تحويل MP3 يبقى عملية منفصلة.
- دُمج جسر الواجهة ومعالجات أزرار المهام في `app.js`، وحُذفت مسارات الخادم الخارجي وتنزيل المتصفح ونسخة المقطع التجريبي المكررة. بقيت وحدات Java وPython منفصلة حسب دورها.

403 يعني أن المصدر رفض ملف التنزيل. قد يكون الرابط المؤقت أو طريقة الاستخراج أو قيود المقطع أو الشبكة سببًا له. لم يصل رابط المقطع الذي فشل عند المستخدم، لذلك لم يُثبت سبب تلك الحالة تحديدًا. اختيار «الأفضل» قد ينزل ملف 4K أكبر؛ 720p أو 1080p أقل حجمًا عندما تتوفر هذه الجودات.

المرجع التقني لمسار يوتيوب البديل: https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide

## الاستخدام

- ألصق رابطًا، أو شاركه إلى «لُقطة» من قائمة المشاركة في تطبيق آخر.
- اضغط «فحص الرابط»، واختر الفيديو أو الصوت أو الصور والدقة والصيغة وFPS المتاح للفيديو، ثم «تحميل».
- يتولى المحرك التنزيل والدمج داخل الهاتف. التحميلات تستمر بخدمة أمامية يظهر إشعارها أثناء العمل، مع مراعاة قيود النظام والبطارية.
- بعد اكتمال التحميل، اضغط «حفظ على الجهاز». يحفظ الفيديو في `Movies/Luqta` والصوت في `Music/Luqta` والصور في `Pictures/Luqta` باستخدام MediaStore، دون إذن شامل لملفات الهاتف.
- «فتح» يشغّل الملف عبر تطبيق مناسب. «مشاركة» يفتح قائمة المشاركة في أندرويد.
- من الإعدادات يمكنك تحديث yt-dlp، وتبديل المظهر من زر المظهر أعلى الصفحة.

الملف يُجهّز أولًا في مساحة التطبيق الخاصة، ثم يُنسخ إلى المعرض أو الموسيقى عند الحفظ اليدوي أو التلقائي. تُحذف النسخة المكررة بعد نجاح الحفظ، والنسخة العامة تبقى بعد حذف التطبيق. مسح السجل بعد التأكيد يحذف العناصر المنتهية ونسخ التطبيق، ويحافظ على المهام الجارية والموقوفة وملفات المعرض. حذف العنصر المنفرد متاح لكل الحالات.

## المميزات

- واجهة عربية وتخطيط يناسب الجوال ومظهر فاتح أو داكن.
- فحص رابط مقطع واحد وعرض بياناته عند توفرها.
- MP4 وWebM، وصوت MP3 بجودة 192 kbps أو M4A.
- اختيار حتى 2160p و120 FPS عند توفرهما معًا في المصدر؛ لا يرفع جودة المقطع أو معدل إطاراته اصطناعيًا.
- مقطع واحد في كل مرة لتجنب تقسيم اتصالك، مع 1–8 أجزاء متزامنة عند دعم المصدر للتنزيل المجزأ، وطابور حتى 100 مهمة.
- سجل محلي، وتقدم لمساري الصوت والفيديو دون القفز إلى 100% قبل تجهيز الملف، ووقف مؤقت واستكمال وإلغاء وإعادة محاولة المهمة.
- حفظ وفتح ومشاركة الملفات.
- المحرك داخل التطبيق: yt-dlp إصدار 2026.8.19 مع yt-dlp-ejs، وPython وFFmpeg وQuickJS من youtubedl-android 0.18.1.
- ملفات ELF الأساسية وتغليف APK محاذاة إلى صفحات 16 KiB، مع تفعيل وضع التوافق الرسمي للأجهزة الحديثة.

AutoHotkey يعمل على ويندوز ولا يُضمّن في تطبيق أندرويد؛ مشاركة الروابط واللصق تؤدي دور الاختصار على الهاتف.

## حدود النسخة

قد ترفض بعض المنصات بعض الروابط حسب قيود الوصول أو تغيرات المنصة. جرّب تحديث المحرك من الإعدادات عند حدوث ذلك. التطبيق لا يتجاوز DRM، ولا يستورد كوكيز حساباتك تلقائيًا. تحميل قوائم تشغيل كاملة والبث المباشر غير مفعّلين.

محرك الفيديو يضبط سقفًا قدره 2 GiB للملف الذي يعلن حجمه، ومحرك الصور حدًا قدره 100 MiB للصورة و200 مليون بكسل، ويتحقق التطبيق من توفر 300 MiB قبل البدء. حجم الفيديو قد يكون تقديريًا. لا توجد مهلة تنزيل كلية قدرها 30 دقيقة. الإلغاء يوقف مجموعة عمليات المحرك وينظف بقايا المهمة بعد توقفها؛ الوقف المؤقت يحتفظ بها للاستكمال. تُترك بقايا المهمة الفاشلة لإعادة المحاولة إلى أن ينظفها المستخدم أو يمسح سجلها.

بعض مكتبات WebP المساعدة داخل حزمة FFmpeg الأصلية تستخدم محاذاة 4 KiB. لذلك فُعّل `android:pageSizeCompat="enabled"` من Android 16، بدل الادعاء بأن كل مكونات التشغيل مبنية أصليًا لصفحات 16 KiB. يلزم اختبار فعلي على الأجهزة ذات الصفحات 16 KiB؛ التوافق الكامل الأصلي يحتاج تحديث هذه المكتبات من المصدر. المرجع: https://developer.android.com/guide/practices/page-sizes#16kb-backcompat-mode

## التحقق الذي أُنجز

- تجميع Java، وتحويل DEX، وربط موارد Android ودمج محركات ARM64.
- التحقق الرسمي من توقيع APK ومحاذاة الصفحات.
- اختبار بروتوكول محرك Python المستخدم بالتطبيق وتنزيل المقطع التجريبي وتحويل MP3/M4A والتحقق من الصوت والصورة والمدة باستخدام FFprobe في بيئة البناء.
- 14 اختبارًا للمحرك تشمل إعداد عدد الأجزاء والوقف الفعلي لنقل MP4 واستكماله عبر Range دون تغيير البايتات، والتنزيل والصوت، 403، تقدم المسارين، اختيار 2160p للفيديو العمودي والأفقي، إعطاء أولوية لأعلى FPS، رفض الهبوط الصامت في الدقة وFPS، والتحقق من الملف الفعلي. يتضمن الاختبار نقل فيديو تجريبي عمودي فعلي 2160×3840 عند 120 FPS عبر DASH محلي، ثم قراءة الملف النهائي بـFFprobe؛ هذا اختبار بمصدر متحكم فيه وليس رابطًا من يوتيوب.
- 11 اختبارًا لصور إنستقرام وتيك توك وفق بيانات محكومة: ألبوم من 10 صور بترتيبها، استبعاد المعاينات المربعة، رفض المعاينة عند غياب بيانات المنشور، ترابط استخراج صور إنستقرام مع yt-dlp، وقراءة بيانات المنشور من صفحة المصدر قبل صورة المعاينة، تنزيل الصور الكاملة الفعلية دون تغيير بايتاتها، اختيار دقة أقل مع بقاء أعلى المشهد وأسفله، رفض بايتات مقصوصة حتى لو وصفتها البيانات كصورة كاملة، منع التكبير الاصطناعي، الألبوم المختلط وحصر كوكيز المصدر في نطاقه.
- 7 اختبارات للصور تشمل JPEG/PNG/WebP بدقة 4K فعلية، حفظ البايتات الأصلية، استخراج صور الصفحة واختيارها، رفض الصورة الأصغر من 4K، قتل العامل أثناء النقل والاستكمال، تغير ETag دون خلط الملفات ورفض Content-Range غير الصحيح.
- 19 تحققًا Java لمنطق استرجاع المهمة والوقف وحماية الملف النهائي وتنظيف ملفات حقيقية، بما فيها بقايا المهام القديمة وتجنب تتبع الروابط الرمزية.
- ثمانية تحققّات Java لترقية المحرك وإصلاح الحزمة مع المحافظة على نسخة أحدث، واختبار نقل الملف الذري.
- فحص عناصر الواجهة وجسر IPC بديل لأزرار الوقف والاستكمال والإلغاء وإعادة المحاولة والحفظ والفتح والمشاركة وتحديث المحرك، ورفض نتيجة الفحص القديمة عند تغيير الرابط، وعرض العناوين كنص آمن، وتمكين 4K العمودي وفصل 4K60 عن 1080p120، وخيارات الصور واختيار صورة الصفحة ورفض الصورة الصغيرة قبل إضافة مهمة 4K، وحفظ إعداد عدد الأجزاء والتنظيف، وإضافة كل صور الألبوم دفعة واحدة، واختيار جودة الصورة، وحذف عنصر مكتمل مع تأكيد وتراجع، وفتح ربط المصدر. 33 طلب IPC بديل نجحت. هذه الاختبارات تستخدم jsdom وجسرًا بديلًا ولا تشغّل أندرويد.


تعذّر تنزيل Chromium في بيئة البناء، لذلك تحقق jsdom من منطق الواجهة ولم يُختبر التخطيط في متصفح كامل. لم تتوفر بيئة أندرويد فعلية أو محاكي لتشغيل APK. اختبار التثبيت وتشغيل محركات ARM64 والحفظ عبر MediaStore والإشعارات على الهاتف يظل مطلوبًا؛ لا تُعد اختبارات محرك Python على الكمبيوتر بديلًا عن ذلك.

## تشغيل فحوص المحرك

```bash
python3 scripts/test_engine.py
python3 scripts/test_images.py
python3 scripts/test_social_photos.py
python3 scripts/test_security.py
```

يلزم yt-dlp مع الاعتماديات الافتراضية وFFmpeg وFFprobe في بيئة الفحص، وPillow لفحص ألوان أعلى الصورة وأسفلها في اختبار التصغير. `scripts/test_ui.cjs` يفحص عناصر الواجهة والطلبات باستعمال jsdom وجسر IPC بديل؛ ليس اختبارًا لتخطيط الشاشة أو للجسر على أندرويد. شغّله بعد `npm install` بواسطة `npm run test:ui`. `scripts/DownloadLifecycleTest.java` يفحص الوقف والتنظيف مع `DownloadState.java` و`DownloadFiles.java`. `scripts/EngineArchiveTest.java` يعمل على Java العادي مع `EngineArchive.java`.

## ملفات المشروع وإعادة البناء

- `app/src/main/java`: واجهة أندرويد، الجسر، إدارة التحميل، الحفظ وخدمة الخلفية.
- `app/src/main/assets`: واجهة الويب المحلية داخل التطبيق ومحرك Python.
- `app/src/main/res/raw/ytdlp`: حزمة yt-dlp وyt-dlp-ejs المدمجة.
- `scripts/build.py`: تنزيل الحزم المثبتة من Maven Central وبناء APK بأدوات Android الرسمية.
- `dependency-lock.json`: بصمات الحزم التي بُني منها التطبيق.
- `scripts/package_source.py`: تجميع الملفات المسموح مشاركتها فقط، مع رفض ملفات المفاتيح والأسرار. مفتاح توقيع النسخة الحالية غير مرفق بالكود.

يلزم Java 17، Android SDK بمكونات `platforms;android-36` و`build-tools;35.0.0`، وECJ 3.38.0. ما يزال التطبيق يستهدف API 35 بحد أدنى API 29؛ استُخدمت موارد API 36 لتعريف خاصية وضع توافق الصفحات. هذا المشروع يُبنى بسكربت Python مباشرة، دون Gradle:

```bash
python3 scripts/build.py --sdk /absolute/path/to/android-sdk --ecj /absolute/path/to/ecj.jar \
  --keystore /private/path/release.p12 --key-alias your-alias \
  --password-file /private/path/password.txt
```

النتيجة في `outputs/Luqta-Android.apk`. اجعل ملفات التوقيع خارج المشروع وبصلاحيات `chmod 600`، واحتفظ بالمفتاح بعيدًا عن حزمة المصدر وأي مستودع عام. لتوقيع نسخة أخرى تحتاج مفتاحك الخاص؛ تحديث النسخة المثبتة مباشرة يحتاج شهادة التوقيع نفسها. GitHub Actions يتطلب إعداد Secrets الخاصة `LUQTA_KEYSTORE_BASE64` و`LUQTA_KEYSTORE_PASSWORD` و`LUQTA_SIGNING_ALIAS`؛ لا يرفع ملف المفتاح ضمن ناتج البناء. يستخدم CI مفتاح PKCS12 بكلمة مرور واحدة للخزنة والمفتاح. لتجميع الكود دون المفاتيح، شغّل `python3 scripts/package_source.py`.
